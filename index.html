Ghost — Safe Database Update SQL

Run this once in Supabase → SQL Editor. It only creates new tables/columns if they don't exist and never deletes or alters your existing data. All your accounts, posts, likes and comments stay exactly as they are.

-- ============================================================ -- Ghost — Safe Add-on SQL (NON-DESTRUCTIVE) -- Run in Supabase SQL Editor. Safe to run multiple times. -- Nothing below deletes or overwrites existing data. -- ============================================================ -- 1) Saves (bookmarks) — saved on the server, per user create table if not exists public.post_saves ( id bigint generated by default as identity primary key, post_id bigint not null, user_email text not null, user_name text, created_at timestamptz not null default now(), unique (post_id, user_email) ); -- 2) Shares — every share to a friend / copy / native share create table if not exists public.post_shares ( id bigint generated by default as identity primary key, post_id bigint not null, sharer_email text not null, sharer_name text, recipient_email text, share_type text not null default 'friend', created_at timestamptz not null default now() ); -- 3) Creator flag on accounts (adds column only if missing) alter table public.system_accounts add column if not exists is_creator boolean not null default false; -- Mark ONLY the oldest account (earliest created_at) as Creator. -- This never touches any other row's data. update public.system_accounts set is_creator = true where system_email = ( select system_email from public.system_accounts order by created_at asc limit 1 ); -- 4) Helpful indexes (created only if missing) create index if not exists idx_post_saves_user on public.post_saves (user_email); create index if not exists idx_post_saves_post on public.post_saves (post_id); create index if not exists idx_post_shares_post on public.post_shares (post_id); create index if not exists idx_post_shares_sharer on public.post_shares (sharer_email); -- 5) Row Level Security — open policies matching your existing tables alter table public.post_saves enable row level security; alter table public.post_shares enable row level security; drop policy if exists "post_saves_all" on public.post_saves; create policy "post_saves_all" on public.post_saves for all using (true) with check (true); drop policy if exists "post_shares_all" on public.post_shares; create policy "post_shares_all" on public.post_shares for all using (true) with check (true); -- Done. Existing tables (system_accounts, home_posts, post_likes, -- post_comments, profile_follows, text_messages) are untouched.
